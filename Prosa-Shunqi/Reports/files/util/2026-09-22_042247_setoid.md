## Representation findings

`leb` is not a numeric order and was therefore not mapped to Lean's `LE`
class. It is the implication preorder on Boolean truth: its constructor stores
`a = true -> b = true`. The production translation preserves this as a small
indexed inductive. Named Lean helpers expose the source's anonymous
reflexivity, transitivity, conjunction, and disjunction compatibility facts
without installing conflicting global order instances.

The source `leqRW` converts MathComp's reflected Boolean Nat comparison into
Coq's proposition-valued Nat order. At the approved Lean boundary both are
represented by `Nat` and `m ≤ n`, so the compiled target is the proof-valued
identity function. A validation-only `rfl` theorem guards that actual body;
the semantic certificate separately relates the two source observations.

Production file: `Prosa/Util/Setoid.lean`.

All three source counterparts compile under pinned Lean 4.33.1/Mathlib, have
no `sorry`, `unsafe`, or custom axiom, and `#print axioms` reports no axioms.

## Semantic-validation history and insight

The first actual-artifact probe established the imported shapes before the
certificate was designed:

- `leb : Bool -> Bool -> SProp`, with the imported constructor carrying an
  implication between imported Boolean equalities;
- `leb_eq` as imported `Iff` between that inductive and the implication;
- `leqRW : forall m n : Lean.Nat, Lean.Nat_le m n -> Lean.Nat_le m n`.

This precheck avoided unfolding irrelevant Lean proof machinery. The one
proof error encountered in the reusable Nat layer was local and diagnostic:
the `reflect` directions for `leP` had initially been reversed. `introT leP`
is the Coq-Nat-order-to-Boolean-truth direction, while `elimT leP` is the
reverse. After correcting that orientation, the common correspondence module
and all three target certificates compiled.

The validator then performed a fresh isolated Lean build, exported the actual
compiled inductive/definition plus the exact theorem statement, imported the
artifact with `rocq-lean-import`, compiled the official complete
`util/setoid.v`, and checked the certificates in the retired pre-9.0 validation baseline. Direct official
source import was used for the Inductive and proof-valued Definition; no
handwritten source slice stood in for them.

Reusable correspondence material added in `SetoidCorrespondence.v`:

- exhaustive Rocq `bool` to imported Lean `Bool` roundtrips;
- Boolean truth/equality correspondence;
- implication and `Iff` logical-relation combinators;
- constructor-observational `leb` correspondence;
- MathComp Boolean Nat order and Coq `Nat.le` correspondence to imported
  Lean `Nat.le`, reusing the certified Nat representation.
